# ブラウザ拡張によるダウンロード自動登録案

## ねらい

BOOTH 等でユーザー自身が通常どおりファイルをダウンロードし、ブラウザのダウンロードフォルダへ保存したあと、ローカルの VR Asset Library に商品情報とファイルを対応付けて自動追加する。

アプリがストアへのログイン、購入履歴同期、ダウンロードの代行をする機能ではない。拡張は、ユーザーがブラウザで行ったダウンロードをライブラリへ渡す補助機能である。

## 推奨する利用フロー

```text
1. BOOTH の商品ページを開く
2. 拡張の「この商品をライブラリへ追加」を押す
   └─ URL、商品名、ショップ、サムネイル候補を取得し、登録待ち状態にする
3. 普段どおり BOOTH のダウンロードボタンでファイルを Downloads へ保存する
4. 拡張が完了したダウンロードを検知する
5. ローカルアプリが、登録待ちの商品情報とダウンロード済みファイルを組み合わせる
6. 「追加しました」通知、または初回のみ確認カードを表示する
   └─ アプリ管理フォルダにコピーする／Downloads のファイルを外部参照する、を設定に従い処理
```

この「ページで明示的に有効化してから、次のダウンロードを取り込む」導線を初期案とする。Downloads フォルダにあるすべての ZIP を無条件に登録しないため、VRChat と無関係なダウンロードや誤った商品への紐付けを防げる。

## 構成

```text
BOOTH / Gumroad の商品ページ
        │  ページ情報を抽出（明示操作時のみ）
        ▼
ブラウザ拡張（Chrome / Edge / Firefox）
        │  ダウンロード完了・商品メタデータを JSON で送る
        ▼
Native Messaging Host（アプリ同梱の小さな Rust 実行ファイル）
        │  ローカル IPC またはアプリ起動引数で転送
        ▼
Tauri デスクトップアプリ
        ├─ SQLite: Asset / AssetFile / SourceMetadata
        └─ ライブラリフォルダへコピー、または外部参照として登録
```

Chrome/Edge 系では拡張が `downloads` 権限でダウンロードを監視でき、ネイティブメッセージングホストとは標準入出力経由で通信する。ホストの許可リストには、この拡張の固定 ID だけを登録する。Firefox も同様のネイティブメッセージング機構を提供する。[Chrome Downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads) [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) [Firefox Native Messaging](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Native_messaging)

Tauri 本体を直接起動するだけでなく、Native Messaging Host を別の小さな companion binary として同梱するのが分かりやすい。拡張が起動していないアプリにも確実にメッセージを渡せ、アプリ更新時も通信形式を独立して保守できる。

## 拡張が担当すること

- BOOTH 商品ページで、ユーザーが押したときだけ商品 URL、タイトル、ショップ URL／名、代表画像候補を取得する。
- 「このタブで次に完了したダウンロード」を登録待ち商品に結び付ける。
- ダウンロード完了イベントを受け、完了済みであること、ファイル名、ローカル保存パス、最終 URL、サイズ、開始／終了時刻をアプリへ伝える。
- アプリが未起動なら Native Messaging Host 経由で起動または受信待ちキューへ保存する。
- 商品ページの解析は `BoothAdapter` のように配布元ごとに分離する。Gumroad 等の追加はアダプターを増やすことで対応する。

拡張に必要な権限は最小にする。初期の BOOTH 対応なら `downloads`、`nativeMessaging`、`storage` と BOOTH の商品ページに限る `host_permissions` を基本とする。ページへの常時アクセス、すべての閲覧履歴、アカウント Cookie をアプリへ送らない。

## アプリが担当すること

- 拡張から来た JSON をスキーマ検証して、登録待ち情報として保存する。
- ダウンロードファイルが実在する通常ファイルか、設定された Downloads フォルダ配下か、サイズが安定しているかを確認する。
- ハッシュを計算し、同一ファイル、同一商品 URL、既存アセットへの追加候補を判定する。
- 既定の保存方式に従ってライブラリへコピーするか、外部参照として登録する。
- 取得したサムネイルはライブラリ内にコピーし、ネットワークがなくても表示できるようにする。
- 失敗・重複・リンク切れは「要確認」キューに入れ、元ファイルを勝手に削除しない。

## 登録状態

| 状態 | 意味 | 次の操作 |
| --- | --- | --- |
| `armed` | 商品ページで登録を有効化したが、まだファイル未完了 | 次のダウンロードを待つ。時間切れで解除 |
| `received` | 拡張から完了ファイル情報を受信 | ファイル検証・ハッシュ計算 |
| `needs_review` | 重複、パス不明、複数ファイル、解析失敗など | UI でアセットへの追加先を選ぶ |
| `imported` | アセット／ファイルとして登録済み | 詳細画面へ移動可能 |
| `ignored` | ユーザーが登録しないと選択 | ファイルには触れない |

## 複数ファイルの扱い

商品によっては本体と追加データが複数回に分けてダウンロードされる。`armed` 状態を一度のダウンロードで即座に消さず、次のいずれかを選べるようにする。

- **一ファイルずつ確定**: 完了した都度、既存アセットへ追加する。
- **まとめて確定**: 「この商品への追加を完了」するまで、受信ファイルを同じ登録待ち商品に蓄積する。
- **時間制限**: 操作がないまま一定時間が過ぎたら確認キューへ入れる。

## 初期リリースに含める範囲

1. Chromium 系（Chrome / Edge）向け Manifest V3 拡張。
2. BOOTH 商品ページ上での手動「ライブラリへ追加」ボタン。
3. 直後に同じタブから完了したダウンロード一件を、アプリへ渡す。
4. アプリ側でコピー管理または外部参照の設定に従って登録し、重複時だけ確認を出す。
5. 拡張・companion host・アプリをまとめてインストール／アンインストールできる Windows インストーラー。

Firefox 対応、複数ファイルのまとめ登録、Gumroad のページ解析、ダウンロードフォルダ監視だけでの自動候補提示は、その後に追加する。

## 安全性とプライバシー

- ログイン Cookie、パスワード、購入履歴、ダウンロード URL の認証トークンを DB やログへ保存しない。
- Native Messaging Host は許可済み拡張 ID 以外からの通信を受け付けない。Chrome の `allowed_origins` はワイルドカードを許さない。[Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)
- 拡張から届くファイルパス・名前・URL はすべて信用せず、アプリ側でパスの正規化、許可フォルダ確認、通常ファイル確認を行う。
- 拡張から受け取った URL をバックグラウンドで自動アクセスしない。商品情報の再取得はアプリで明示的に実行する。
- ダウンロードしたファイルを実行・展開しない。アーカイブ解析を将来追加する場合も、パストラバーサルと展開爆弾対策を別途入れる。

## 後から検討する案

- アプリが Downloads フォルダを監視し、未登録の ZIP／UnityPackage を「登録候補」として表示する。これは拡張なしでも使えるが、商品ページの情報との正確な対応付けはできない。
- ダウンロード時にアプリ専用の一時受信フォルダを選べるようにする。ブラウザの既定ダウンロード操作を変えずに済む、Downloads 経由の方式を初期案として優先する。
- アセットのダウンロードリンクではなく、商品 URL を拡張メニューからアプリへ送るだけの簡易モード。ファイルは後からアプリへドラッグ＆ドロップする。
